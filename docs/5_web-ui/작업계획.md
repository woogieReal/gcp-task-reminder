# 웹 UI 구현 작업계획

## 목표

스마트폰 브라우저에서 한 손으로 쉽게 알림을 예약·확인·취소할 수 있는 웹 화면을 만든다.
task 4의 최소 로그인 페이지를 블루프린트 Phase 3 예약 화면으로 확장하고, 모바일 UI 원칙(한 열, 44px 터치 대상, 16px 입력 글꼴)을 적용한다.
시각 계산·검증·표시 형식 같은 화면 로직은 순수 함수 모듈로 분리해 자동 테스트로 검증한다.

## 작업 범위

- 블루프린트 Phase 3: 로그인 화면, 예약 화면(상단·등록 폼·예약 목록), 공통 동작(401 처리, 중복 요청 방지)
- 블루프린트 Phase 3 모바일 UI 원칙
- task 4 이월: GIS 버튼 고정 폭(표준 → 개인화 버튼 전환 시 크기 변화 완화), 파비콘
- 화면 로직 순수 함수 모듈(`public/time.js`)과 자동 테스트
- 제외: 서버 API 변경(필요 시에만), 배포(task 6), 실제 휴대폰 검증(배포 후 task 7)

## 세부 작업 목록

### 1단계: 화면 로직 모듈 (`public/time.js`, 순수 함수)

- [x] 빠른 선택 시각 계산: `10분 후`, `30분 후`, `1시간 후`, `3시간 후`(현재 기준, 분 단위 내림), `내일 오전 9시`(로컬 시간대 기준 다음 날 09:00)
- [x] `datetime-local` 값 ↔ `Date` 변환 (로컬 시간 해석), API 전송용 ISO 8601(UTC) 문자열 생성
- [x] 등록 가능 여부 판단: 메시지 공백·4000자 초과, 시각 미입력·과거·30일 초과 → 비활성 사유 문구 반환 (서버 검증 규칙과 동일)
- [x] 표시 형식: 예약 시각 `10/12 (일) 14:30`, 남은 시간 `2시간 15분 후` / `3일 4시간 후` / `1분 이내`

### 2단계: 화면 구조와 동작 (`public/index.html`, `public/app.js`)

- [x] 로그인 화면: 서비스 이름 + Google 로그인 버튼(고정 폭), 비허용 계정 안내
- [x] 예약 화면 상단: 로그인한 이메일, 로그아웃 버튼
- [x] 등록 폼: 여러 줄 메시지 입력 + 글자 수 표시, 빠른 선택 버튼 5개(누르면 직접 지정 칸에 시각 채움), `datetime-local` 직접 지정(분 단위), 등록 버튼(불가 시 비활성 + 사유 표시)
- [x] 등록 성공 시 폼 초기화 + 목록 갱신, 실패 시 서버 에러 메시지 표시
- [x] 예약 목록: 시각 오름차순, 메시지·예약 시각·남은 시간, 재시도 중 표시(시도 횟수·마지막 오류), 항목별 `취소`(확인 후 삭제 → 갱신), 빈 상태 안내
- [x] 목록 갱신: 새로고침 버튼, 페이지가 다시 보일 때(`visibilitychange`), 남은 시간 표시는 주기적으로 다시 계산
- [x] 공통: API `401` → 로그인 화면 전환, 요청 중 버튼 비활성화, 사용자 입력은 `textContent`로만 렌더링(XSS 방지)
- [x] 파비콘(`public/favicon.svg`) 추가 및 연결

### 3단계: 모바일 우선 스타일 (`public/style.css`)

- [x] 한 열 레이아웃, 360px 기준, 넓은 화면은 가운데 정렬 최대 폭
- [x] 터치 대상 최소 44×44px, 입력 글꼴 16px 이상, 가로 스크롤 없음
- [x] 빠른 선택 버튼과 등록 버튼을 크게, 엄지로 누르기 쉬운 배치
- [x] 시스템 다크 모드(`prefers-color-scheme`) 대응
- [x] 인라인 스타일 없이 외부 스타일시트만 사용 (CSP `style-src 'self'` 유지)

### 4단계: 자동 테스트

- [x] `public/time.js` 테스트: 빠른 선택 시각(자정·월말 경계 포함), 변환, 등록 가능 여부(경계값 4000자·30일), 표시 형식(요일·남은 시간 단위)
- [x] 테스트는 시간대를 `Asia/Seoul`로 고정해 실행 환경과 무관하게 동일한 결과가 나오게 함
- [x] `public/`에 테스트 파일을 두지 않음 (정적 파일로 배포되므로 `test/` 디렉터리에 배치)
- [x] `npm run typecheck`, `npm test`, `npm run build` 통과
  - 결과: 12개 파일 109개 테스트 통과 (화면 로직 26개 추가)

### 5단계: 로컬 수동 검증

- [x] compose에서 서버 응답 확인: `/`, `/style.css`, `/time.js`, `/favicon.svg` 200, CSP 헤더 유지
  - 결과: 5개 파일 모두 200, 올바른 Content-Type
- [x] (사용자) Chrome 개발자 도구 기기 모드 360px 폭에서 확인: 로그인 버튼 전환 시 크기 변화 없음, 가로 스크롤 없음, 콘솔 CSP 오류 없음
  - 1차 결과: 레이아웃·가로 스크롤 없음·파비콘 정상. 단 새 CSP 오류(인라인 style **속성**, 해시 `OXbX…`): 버튼 폭을 지정하자 GIS가 폭이 들어간 style 속성을 주입. 폭이 화면마다 달라 해시 허용 불가 → 방식 결정 필요
  - 1차 결과: 로그인 안내 문구가 단어 중간("받으세/요")에서 줄바꿈 → `word-break: keep-all` 적용
  - 조치(사용자 결정 A안): `style-src`에 `'unsafe-inline'` 허용, task 4의 GIS `<style>` 해시 제거. `script-src`는 그대로 엄격하게 유지(테스트로 확인). 블루프린트 공통 규칙에 사유 기록
  - 사용자 제보: 알림 시각의 분 칸에 `40`을 입력하면 `04`로만 입력됨 → 원인: 입력 이벤트마다 `min`/`max` 속성을 갱신해 Chrome이 편집 중인 칸을 확정. `min`/`max`는 포커스 시에만 갱신하도록 수정
  - 2차 결과(사용자): CSP 오류 없음, 분·시 두 자리 입력 정상, 빠른 선택 후 직접 수정 정상
- [x] (사용자 추가 요청) 알림 시각 기본값 `지금 + 5분`
  - 구현: `public/time.js`에 `defaultScheduleTime` 추가(테스트 3개). 직접 수정·빠른 선택 전까지는 30초 주기·탭 복귀 시 기본값을 다시 계산(입력칸 편집 중에는 갱신하지 않음), 등록 성공 후 기본값 복원. 블루프린트 Phase 3 반영
- [x] (사용자) 빠른 선택 5개가 각각 올바른 시각을 채우는지, 직접 지정으로 미세 조정되는지
  - 결과: 사용자 확인 "다 정상 작동" (분 입력 수정 후)
- [x] (사용자) 과거·30일 초과 시각에서 등록 버튼 비활성과 사유 표시
  - 결과: 사용자 확인 (기본값 5분 표시, 메시지 입력 시 등록 활성, 과거·30일 초과 시 비활성 + 사유 표시)
- [x] (사용자) 1~2분 뒤로 예약 등록 → 목록 표시(남은 시간) → 텔레그램 수신은 배포 전이라 불가하므로, 등록 후 `취소`로 목록·큐에서 사라지는지 확인
  - 결과: 등록 토스트 → 목록(`11/1 (일) 16:20`, 남은 시간) → 취소 확인창 → 취소 토스트 (스크린샷)
- [x] 검증 후 큐에 테스트 태스크가 남지 않았는지 확인
  - 결과: `gcloud tasks list` 0건
