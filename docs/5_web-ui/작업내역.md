### 주요 결정 사항
- **화면 로직을 `public/time.js` 순수 함수로 분리:** 시각 계산과 표시 형식은 경계값(자정·월말·연말, 30일, 4000자)에서 틀리기 쉬워 자동 테스트가 필요하다. DOM과 분리하면 브라우저 없이 vitest로 검증할 수 있다.
- **테스트를 `test/public/`에 배치하고 시간대 고정:** `public/`은 그대로 정적 배포되므로 테스트 파일을 같은 곳에 두지 않았다. 로컬 시간대를 쓰는 로직이라 `TZ=Asia/Seoul`로 고정해 실행 환경과 무관하게 결과를 같게 했다.
- **빠른 선택은 절대 시각을 입력칸에 채움:** 사용자가 등록 전에 항상 최종 시각을 보고 미세 조정할 수 있게 했다(블루프린트 설계). 기본값만은 사용자가 건드리기 전까지 자동 갱신해 화면을 오래 열어둬도 과거 시각이 되지 않게 했다.
- **CSP `style-src 'unsafe-inline'`(사용자 결정 A안):** GIS가 버튼 폭에 따라 내용이 달라지는 인라인 style 속성을 주입해 해시로 고정할 수 없었다. 사용자 입력은 모두 `textContent`로 렌더링하고 HTML 주입 API를 쓰지 않아 CSS 주입 경로가 없으며, `script-src`는 인라인 없이 유지해 스크립트 실행은 계속 막는다. 대안(B안: 폭 고정 + `'unsafe-hashes'` + 해시)은 Google의 스타일 변경 때마다 깨지는 유지보수 부담이 있어 택하지 않았다.
- **확인 대화상자는 `window.confirm` 사용:** 휴대폰 브라우저에서 기본 대화상자가 가장 익숙하고 추가 구현이 필요 없다.

### 이슈 & 해결
- **새 CSP 오류(인라인 style 속성):** GIS 버튼 폭을 지정하자 폭이 들어간 style 속성이 주입되어 task 4의 해시로는 막을 수 없었다. 사용자와 A안을 결정해 `style-src 'unsafe-inline'`을 적용했다.
- **로그인 안내 문구가 단어 중간에서 줄바꿈("받으세/요"):** `word-break: keep-all`로 한글을 띄어쓰기 단위로만 줄바꿈하게 했다. 긴 메시지는 `overflow-wrap: anywhere`로 계속 줄바꿈된다.
- **분 칸에 `40`을 입력하면 `04`로만 입력됨(사용자 제보):** 입력 이벤트마다 `datetime-local`의 `min`/`max`를 갱신해 Chrome이 편집 중인 칸을 확정했기 때문이다. `min`/`max`는 포커스 시에만 갱신하고, 30초 주기 갱신에서도 건드리지 않게 수정했다.
- **알림 시각 기본값 5분(사용자 추가 요청):** `defaultScheduleTime`을 추가하고, 직접 수정·빠른 선택 전에는 자동 재계산, 등록 성공 후 기본값 복원하도록 했다.
- **남은 시간 `1분 이내` 표시 문의:** 빠른 선택은 누른 순간 기준 절대 시각이므로, 누른 뒤 기다렸다가 등록하면 그만큼 남은 시간이 줄어드는 의도된 동작임을 안내했다.
- **다음 task로 이월:** 실제 휴대폰 확인, 텔레그램 수신, 재시도 표시 확인(task 7).
