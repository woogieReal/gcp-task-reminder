### 주요 결정 사항
- **실행 흐름 확인은 서버 로그 기준으로 객관화:** 사용자 수신 확인과 별도로 Cloud Run 요청 로그(User-Agent, 상태 코드)와 앱 로그(`retry=0`)로 "Cloud Tasks가 실제 OIDC 토큰으로 첫 시도에 인증을 통과했다"는 것을 증거로 남겼다. 사용자가 본 도착 시각(49분)이 로그(59분)와 다를 때도 로그로 바로 정정할 수 있었다.
- **예약 A는 기본값(지금 + 5분)으로 등록:** task 5에서 추가한 기본값 기능을 실제 사용 흐름으로 함께 검증하고, A가 실행되기 전에 큐 상태(B 취소 후 A만 존재)를 확인할 여유를 확보했다.
- **A 실행 시각 이후 자동 점검:** 백그라운드로 실행 시각 직후의 큐·로그를 조회해 사용자를 기다리지 않고 결과를 확보했다.
- **iOS 전용 스타일은 기능 감지로 한정:** `appearance: none`은 데스크톱 Chrome의 달력 아이콘을 없앨 수 있어 `@supports (-webkit-touch-callout: none)`(iOS Safari만 지원)으로 범위를 제한했다. 폭 관련 규칙(`min-width: 0`, `max-width: 100%`)은 모든 브라우저에 적용해도 무해하다.

### 이슈 & 해결
- **iOS Safari에서 알림 시각 입력칸이 카드 밖으로 넘침:** iOS의 `datetime-local`은 고유 최소 폭이 있어 `width: 100%`를 무시한다. task 5에서 사용한 데스크톱 Chrome 기기 모드로는 재현되지 않아 실제 기기 검증에서 처음 드러났다. 폭 제한 해제와 iOS 전용 기본 모양 해제·왼쪽 정렬로 수정했고, 배포(리비전 `reminder-api-00004-km4`) 후 사용자가 정상 표시와 선택기 동작을 확인했다.
- **다른 계정 로그인 시 400 화면:** 오류가 아니라 OAuth 동의 화면 Testing 상태의 의도된 차단(`access_denied`)이다. 앱 단계의 두 번째 잠금(허용 이메일 확인, 403)은 자동 테스트로 검증되어 있다.
- **알림 도착 시각 49분 보고:** 서버 발송 로그 16:59:00, 예약 등록 16:54로 49분은 불가능해 확인을 요청했고, 사용자가 59분을 잘못 본 것으로 정정했다.
- **후속 작업:** Artifact Registry 이미지 정리 정책(최근 5개 유지)은 블루프린트 5장에 등록되어 있다.
