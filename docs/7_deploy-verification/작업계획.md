# 운영 배포 검증 작업계획

## 목표

Cloud Run에 배포된 실제 서비스에서 프로젝트의 핵심 흐름을 처음부터 끝까지 검증한다.
휴대폰 브라우저에서 로그인 → 예약 → Cloud Tasks 지연 실행 → 실제 OIDC 토큰으로 `/trigger` 호출 → 텔레그램 수신까지 확인하고,
취소한 예약은 실행되지 않는 것과 운영 환경의 보호 장치가 동작하는 것을 확인해 task 1~6의 결과를 최종 검증한다.

## 작업 범위

- 블루프린트 7장 5단계(보호 확인), 6단계(휴대폰 기능 확인), 7단계(로그·큐 확인)
- 실제 휴대폰에서 모바일 UI 확인 (task 5에서 데스크톱 기기 모드로만 확인한 부분)
- 이전 task 이월 확인: 실제 Cloud Tasks OIDC 토큰으로 `/trigger` 통과(task 4), 실제 휴대폰 화면·텔레그램 수신(task 5)
- 제외: 코드 변경(문제가 발견되면 원인 분석 후 Act에서 수정), 후속 작업(이미지 정리 정책)

## 세부 작업 목록

### 1단계: 운영 환경 보호 확인 (에이전트, curl)

- [x] 세션 없이 `/api/reminders`, `/api/me` → `401`
  - 결과: 둘 다 `401`, 위조 세션 쿠키로 `POST /api/reminders`도 `401`
- [x] 토큰 없이·위조 토큰으로 `/trigger` → `401`
  - 결과: 토큰 없음·위조 토큰 `401`. 추가로 실제 Google 서명 ID 토큰(내 사용자 계정, audience·발급 주체 불일치)도 `401`
- [x] 허용되지 않은 `Origin`의 상태 변경 요청 → `403`
  - 결과: 다른 Origin `403`, JSON이 아닌 form 전송 `403`
- [x] (선택, 사용자) 다른 Google 계정으로 로그인 시도 → Google 단계(테스트 사용자 아님) 또는 앱 `403`으로 차단
  - 결과: 다른 계정으로 시도 시 Google의 400 오류 화면(테스트 사용자가 아닌 계정의 `access_denied`)에서 차단. Cloud Run 로그에 해당 시도의 `/auth/google` 요청 없음 → Google 단계에서 막혀 앱까지 오지 않음 (이중 잠금의 1단계 동작)

### 2단계: 휴대폰 기능 확인 (사용자)

- [x] 휴대폰 브라우저로 운영 URL 접속 → 허용 계정 로그인 → 예약 화면 표시
  - 결과: iPhone Safari(iOS 18.7)에서 로그인 후 목록 조회 `200` (Cloud Run 요청 로그)
- [x] 모바일 화면 확인: 가로 스크롤 없음, 입력칸을 눌렀을 때 화면 확대 없음, 버튼을 누르기 쉬움
  - 1차 결과(iPhone Safari): 가로 스크롤 없음, 입력 시 확대 없음. **알림 시각 입력칸이 카드 밖으로 넘침**(값도 가운데 정렬)
    - 원인: iOS Safari의 `datetime-local`은 고유 최소 폭이 있어 `width: 100%`를 무시함. 데스크톱 Chrome 기기 모드에서는 재현되지 않아 task 5에서 발견 못 함
    - 조치(`public/style.css`): `display: block`, `min-width: 0`, `max-width: 100%` 적용. iOS 전용(`@supports (-webkit-touch-callout: none)`)으로 `appearance: none`과 왼쪽 정렬 적용(데스크톱 Chrome 달력 아이콘 유지).
  - 2차 결과: 커밋 `2a4c507` 배포(run `41287604391` 성공, 리비전 `reminder-api-00004-km4`) 후 사용자 확인 — 입력칸이 카드 안에 맞고 왼쪽 정렬, 날짜·시간 선택기 정상
- [x] 예약 A: 직접 지정으로 2~3분 뒤 시각에 등록 → 목록에 남은 시간과 함께 표시
  - 결과: 기본값(지금 + 5분)으로 등록, `POST /api/reminders` `201`, 태스크 `64022357104021569801` 예약 시각 16:59 KST
- [x] 예약 B: 같은 방식으로 하나 더 등록 → `취소` → 목록에서 사라짐
  - 결과: `POST` `201` → `DELETE` `204` → 목록 재조회 `200`
- [x] 예약 A 시각에 텔레그램 `[리마인더] ...` 수신 → 새로고침 시 목록에서 사라짐
  - 결과: 사용자 텔레그램 수신 확인, 새로고침 후 목록에서 사라짐. 서버 발송 시각 16:59:00 KST(로그)
- [x] 예약 B 시각이 지나도 알림이 오지 않음
  - 결과: 사용자 확인, B 알림 없음

### 3단계: 로그·큐 확인 (에이전트)

- [x] 예약 A·B 등록 직후 `gcloud tasks list`로 큐에 태스크 존재, B 취소 후 A만 남음
  - 결과: B 취소 직후 큐에 A 1건만 존재(dispatch 0회)
- [x] Cloud Run 로그에서 예약 A의 `/trigger` 요청이 `200`, `trigger: 발송 완료 (task=…, retry=0)` 기록 확인 → 실제 Cloud Tasks OIDC 토큰으로 인증 통과
  - 결과: 07:59:00Z `POST /trigger` `200`, User-Agent `Google-Cloud-Tasks`, 지연 1.53초. 앱 로그 `trigger: 발송 완료 (task=64022357104021569801, retry=0)` → 첫 시도에 실제 OIDC 토큰 검증 통과
- [x] 로그에 OIDC 검증 실패·500 오류가 없고, 봇 토큰·쿠키 값이 출력되지 않음
  - 결과: 최근 30분 5xx 0건. OIDC 검증 실패 로그는 1단계 curl 점검(위조 토큰, 사용자 ID 토큰)에서 의도적으로 발생한 2건뿐(`Wrong number of segments`, `Wrong recipient`). 최근 1시간 로그에서 봇 토큰·세션 쿠키 값 0건
- [x] 최종적으로 큐 0건
  - 결과: 17:00:37 기준 0건

### 4단계: 정리

- [x] 블루프린트 task 표에 task 1~7 완료 상태 반영, 후속 작업 목록 확인
  - 결과: 블루프린트 5장에 진행 상태(task 1~7 완료) 추가. 후속 작업: Artifact Registry 이미지 정리 정책(최근 5개)

## 완료 기준

- 운영 URL에서 보호된 엔드포인트가 `401`/`403`으로 차단된다
- 휴대폰에서 로그인 → 예약 → 예약 시각에 텔레그램 알림 수신 → 목록에서 사라짐이 확인된다
- 취소한 예약은 알림이 오지 않고 큐에서도 사라진다
- Cloud Run 로그로 실제 Cloud Tasks OIDC 토큰이 `/trigger` 인증을 통과했음이 확인된다
- 검증 후 큐에 남은 태스크가 없다
