# 인증 구현 작업계획

## 목표

Cloud Run이 `allUsers`로 공개되어 있으므로, 앱이 모든 보호를 담당하도록 인증 계층을 구현한다.
브라우저는 Google 로그인 → 서버 서명 세션 쿠키로, Cloud Tasks는 OIDC 토큰 검증으로 접근을 제한하고, CSRF 방어와 보안 헤더를 적용한다.
이 task가 끝나야 Cloud Run 배포(task 6)가 가능하다.

## 작업 범위

- 블루프린트 2장 인증 모델: `POST /auth/google`, `POST /auth/logout`, `GET /api/me`, `GET /api/config`
- 세션 쿠키(서버 서명, stateless), `/api/*` 세션 미들웨어
- `/trigger` OIDC 토큰 검증, `SKIP_TRIGGER_AUTH`(development 한정) 적용
- CSRF 방어(`Content-Type` + `Origin` 검사), 보안 헤더(CSP 등)
- 로컬 로그인 수동 검증용 **최소 로그인 페이지**(`public/index.html`)와 정적 파일 서빙, runtime 이미지의 `public/` 복사 (task 2 이월). 예약 화면 등 본격적인 UI는 task 5
- 제외: 예약 화면 UI(task 5), 배포(task 6)

## 세부 작업 목록

### 1단계: 설계 확정 및 의존성

- [x] **확인:** Google Identity Services가 동작하는 데 필요한 CSP 지시어, `Cross-Origin-Opener-Policy`, `Referrer-Policy` 값을 공식 문서로 확인 (보안 헤더 기본값이 GIS를 막지 않도록)
  - 결과(공식 가이드 "Get your Google API client ID"): CSP `script-src https://accounts.google.com/gsi/client`, `frame-src`·`connect-src https://accounts.google.com/gsi/`, `style-src https://accounts.google.com/gsi/style`. COOP는 `same-origin-allow-popups`(FedCM 비활성 시 필요, 활성 시에도 무해). Referrer-Policy는 `strict-origin-when-cross-origin` 권장 → helmet 기본값 `no-referrer`를 덮어써야 함
- [x] 의존성 설치: `google-auth-library`(ID 토큰·OIDC 검증), `helmet`(보안 헤더)
- [x] 세션 쿠키는 외부 라이브러리 없이 Node `crypto` HMAC-SHA256 서명으로 구현 (서명 비교는 timing-safe)

### 2단계: 인증 모듈

- [x] `auth/google.ts`: Google ID 토큰 검증 (서명·만료·발급자는 라이브러리, audience = OAuth Client ID), `email_verified = true`, `email = ALLOWED_EMAIL` 확인. 결과를 "유효하지 않은 토큰"과 "허용되지 않은 계정"으로 구분
- [x] `auth/session.ts`: 세션 생성(`{ email, exp }` 서명), 검증(서명·만료), 쿠키 발급·삭제(`HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, 7일), 인증 미들웨어(`/api/*`, 실패 시 `401`)
- [x] `auth/oidc.ts`: `/trigger`용 미들웨어. `Authorization: Bearer` 토큰을 audience = `SERVICE_URL`로 검증하고 발급 SA 이메일 = `TASKS_INVOKER_SA_EMAIL` 확인, 실패 시 `401`. `config.skipTriggerAuth`일 때만 생략
- [x] `auth/csrf.ts`: `POST`·`DELETE` 요청에 `Content-Type: application/json` 요구, `Origin`이 허용 목록(`SERVICE_URL`, development일 때 `http://localhost:<PORT>`)과 일치해야 함, 실패 시 `403`. `/trigger`에는 적용하지 않음(OIDC로 보호)
- [x] 토큰 검증기는 인터페이스로 주입해 테스트에서 mock 사용

### 3단계: 라우트와 앱 구성

- [x] `routes/auth.routes.ts`: `POST /auth/google`(`{ credential }` → `204` + 세션 쿠키, 무효 토큰 `401`, 비허용 계정 `403`), `POST /auth/logout`(`204` + 쿠키 삭제)
- [x] `GET /api/me`(세션 → `{ email }`), `GET /api/config`(인증 없음, `{ googleClientId }`)
- [x] `app.ts`: 보안 헤더 → 정적 파일(`public/`) → CSRF → 라우트 순서 구성, `/api/reminders`에 세션 미들웨어, `/trigger`에 OIDC 미들웨어
- [x] `index.ts`: 실제 토큰 검증기 연결
- [x] 로그에 ID 토큰, 쿠키 값, 세션 키가 출력되지 않도록 확인

### 4단계: 최소 로그인 페이지와 이미지

- [x] `public/index.html` + `public/app.js`: `/api/config`로 Client ID를 받아 GIS 로그인 버튼 표시 → credential을 `POST /auth/google` → `/api/me` 결과(로그인한 이메일)와 로그아웃 버튼 표시. 인라인 스크립트 없이 CSP를 지키도록 작성. task 5에서 예약 화면으로 확장
- [x] `Dockerfile` runtime 스테이지에 `public/` 복사, `compose.yaml`에 `public/` 마운트

### 5단계: 자동 테스트 (블루프린트 6장 task 4 케이스)

- [x] Google 로그인: 허용 이메일 → `204` + 세션 쿠키(속성 확인), 다른 이메일·`email_verified=false` → `403`, 검증 실패 토큰·`credential` 누락 → `401`/`400`
- [x] 세션: 세션 없음·위조(서명 불일치)·만료 → `/api/*` `401`, 유효 세션 → `/api/me` `200`, 로그아웃 시 쿠키 삭제
- [x] CSRF: `Origin` 없음·불일치 → `403`, `Content-Type`이 JSON 아님 → `403`, 허용 `Origin` → 통과, `GET`은 검사 안 함
- [x] OIDC: 토큰 없음·검증 실패(audience 불일치 포함)·다른 SA 이메일·`email_verified=false` → `401`, 정상 → 발송 진행
- [x] `SKIP_TRIGGER_AUTH`: development에서는 토큰 없이 통과, production에서는 무시(`401`)
- [x] 보안 헤더: CSP에 GIS 도메인 허용, `X-Powered-By` 없음, COOP·Referrer-Policy 값 확인
- [x] 기존 task 3 테스트가 인증 추가 후에도 통과하도록 테스트용 세션·Origin 헬퍼 정리
  - 결과: `src/test/helpers.ts`(테스트 설정, 가짜 토큰 검증기, 세션 쿠키 생성)를 추가하고 빌드에서 제외(`tsconfig.build.json`)
- [x] `npm run typecheck`, `npm test`, `npm run build` 통과

### 6단계: 로컬 수동 검증 (사용자 브라우저)

- [x] `docker compose up --build` 후 `http://localhost:8080`에서 허용 계정(`woogiereal@gmail.com`)으로 Google 로그인 성공, 이메일 표시 (사용자 수행)
  - 1차 결과: 로그인·로그아웃 성공. 단 콘솔 오류 확인됨 (아래 항목)
- [x] 브라우저 개발자 도구 콘솔에 CSP 위반 오류가 없는지 확인 (사용자 수행)
  - 1차 결과: 오류 있음
    - `The given origin is not allowed for the given client ID`(403): GIS는 로컬 테스트 시 `http://localhost`와 `http://localhost:8080`을 **둘 다** 승인된 원본에 등록해야 함 → OAuth Client에 `http://localhost` 추가 필요(사용자 콘솔 작업), 블루프린트 Phase 0 반영
    - 인라인 스타일 CSP 위반 + 큰 G 로고, COOP postMessage 경고: 원본 거부로 GIS가 대체 버튼·팝업 흐름으로 동작하면서 발생한 부수 효과로 판단. CSP는 완화하지 않고 원본 수정 후 재확인
    - `initialize() is called multiple times` 경고: 로그아웃 시 재초기화하던 코드 수정(페이지당 1회 초기화)
    - `GET /api/me 401`: 비로그인 상태의 정상 응답 (브라우저가 4xx를 콘솔에 표시)
  - 2차 결과(`http://localhost` 원본 추가 후): 원본 오류 해소, 개인화 버튼 정상. 단 새로고침마다 큰 G 로고가 약 0.5초 보였다가 버튼으로 바뀜
    - 원인: GIS가 iframe 버튼 로드 전 임시 버튼에 `<style>`을 주입하는데 `style-src`가 막아 SVG가 원래 크기로 표시됨 (원본 문제와 무관하게 매 로드 발생 → 1차 판단 정정)
    - 조치: `'unsafe-inline'` 대신 Chrome이 제시한 해당 `<style>`의 sha256 해시만 `style-src`에 허용. Google이 스타일을 바꾸면 해시 갱신 필요(로그인 기능에는 영향 없음)
    - COOP `would block the window.postMessage`: 로그인 팝업(Google 페이지)의 정책에서 나오는 보고성 로그. 서버 헤더로 해결 불가, 로그인 정상 완료 → 허용
  - 3차 결과(해시 적용 후): CSP 위반 오류 0건, 큰 G 로고 깜빡임 해소. 새로고침 시 표준 버튼("Google 계정으로 로그인", 컨테이너 폭)이 잠깐 보였다가 개인화 버튼으로 바뀌는 것은 GIS의 정상 동작. 남은 로그는 `GET /api/me 401`(정상), COOP 보고 로그(허용), `favicon.ico 404`(파비콘 미작성, task 5에서 추가)
    - task 5 반영 사항: `renderButton`에 고정 `width`를 지정해 버튼 전환 시 크기 변화를 줄이고, 파비콘 추가
- [x] 로그아웃 후 `/api/me` `401` 확인
  - 결과: 로그아웃 후 로그인 버튼으로 전환, 콘솔에 `GET /api/me 401` 확인
- [x] `curl`로 세션 없이 `/api/reminders` → `401`, 잘못된 `Origin`으로 `POST` → `403`, 토큰 없이 `/trigger`(SKIP 미설정) → `401` 확인
  - 결과(compose): `/api/me`·`/api/reminders` 세션 없음 `401`, 잘못된 Origin `403`, 가짜 credential `401`, `SKIP_TRIGGER_AUTH=true`(dev)일 때 `/trigger` 통과, `SKIP_TRIGGER_AUTH=false`로 띄운 컨테이너에서 토큰 없음·위조 토큰 `401`. 응답 헤더에 CSP(GIS 도메인)·COOP·Referrer-Policy 확인
- [x] runtime 이미지 빌드 후 `/`가 로그인 페이지를 반환하는지 확인
  - 결과: `/` 로그인 페이지, `/app.js` `200`, production CSP에 `upgrade-insecure-requests` 포함
