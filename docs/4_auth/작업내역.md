### 주요 결정 사항
- **세션을 외부 라이브러리 없이 HMAC 서명 쿠키로 구현:** 서버 저장소가 필요 없어 Cloud Run 인스턴스가 여러 개여도 동작하고, 의존성을 줄였다. 서명 비교는 `timingSafeEqual`로 한다. 개별 세션 강제 만료는 안 되지만 `session_secret_version`을 올려 전체를 무효화할 수 있다.
- **Google ID 토큰을 쿠키에 저장하지 않음:** 로그인 시 한 번 검증한 뒤 서버가 서명한 짧은 세션 토큰만 발급해, Google 토큰 수명과 앱 세션을 분리했다.
- **무효 토큰 `401`과 비허용 계정 `403` 구분:** 토큰 자체 문제와 권한 문제를 화면에서 다르게 안내할 수 있게 했다.
- **CSRF는 토큰 대신 JSON Content-Type + Origin 검사:** 다른 사이트의 form 전송은 JSON Content-Type을 만들 수 없고 브라우저 fetch는 Origin을 위조할 수 없다. `SameSite=Lax`와 함께 단일 사용자 앱에 충분하며 프런트엔드 구현이 단순하다. localhost Origin은 development에서만 허용한다.
- **CSP는 GIS 공식 가이드 기준으로 최소 허용:** `script-src`·`style-src`·`frame-src`·`connect-src`에 GIS 경로만 추가하고, COOP는 `same-origin-allow-popups`, Referrer-Policy는 `strict-origin-when-cross-origin`(helmet 기본 `no-referrer`는 GIS를 막음)으로 설정했다. http://localhost에서는 `upgrade-insecure-requests`를 뺐다.
- **GIS 인라인 `<style>`은 `'unsafe-inline'` 대신 sha256 해시로 허용:** 모든 인라인 스타일을 허용하지 않고 해당 스타일 하나만 허용한다. Google이 스타일을 바꾸면 해시 갱신이 필요하지만 로그인 기능에는 영향이 없다.
- **최소 로그인 페이지를 task 4에 포함:** 브라우저 로그인 검증 없이는 완료 기준을 확인할 수 없어, task 5 범위였던 정적 파일 서빙과 `public/` 이미지 포함을 앞당겼다.

### 이슈 & 해결
- **1차: `The given origin is not allowed for the given client ID`(403):** GIS는 로컬 테스트 시 `http://localhost`와 `http://localhost:8080`을 모두 승인된 원본에 등록해야 한다. 사용자가 OAuth Client에 `http://localhost`를 추가했고 블루프린트 Phase 0에도 반영했다.
- **1차: `initialize() is called multiple times` 경고:** 로그아웃할 때마다 GIS를 재초기화하던 코드를 페이지당 1회 초기화 후 버튼만 다시 그리도록 수정했다.
- **2차: 새로고침마다 큰 G 로고가 약 0.5초 표시:** 원본 문제의 부수 효과로 보았던 1차 판단을 정정했다. GIS가 개인화 버튼(iframe) 로드 전 임시 버튼에 주입하는 `<style>`이 CSP에 막혀 SVG가 원래 크기로 보인 것이다. Chrome이 제시한 해시를 `style-src`에 추가해 해소했다.
- **허용한 로그:** `GET /api/me 401`(비로그인 상태 확인의 정상 응답), COOP `would block the window.postMessage`(Google 로그인 팝업 측 정책의 보고성 로그, 서버에서 해결 불가), `favicon.ico 404`(task 5에서 파비콘 추가).
- **검증 1차 NEED_ACT:** `src/test/helpers.ts`, `tsconfig.build.json`이 [변경 대상 파일]에 없어 보완 후 재검증 PASS.
- **다음 task로 이월:** 버튼 고정 폭·파비콘·모바일 UI(task 5), 실제 Cloud Tasks OIDC 토큰으로 `/trigger` 통과 확인(task 7), GIS 스타일 변경 시 해시 갱신.
