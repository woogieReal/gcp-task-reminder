### 주요 결정 사항
- **WIF로 키 없이 인증:** GitHub에는 식별자 2개만 Environment Variables로 두고 비밀값을 저장하지 않는다. 접근은 GCP의 `attribute_condition`(저장소 + `main`)과 IAM 바인딩으로 제한된다.
- **워크플로는 이미지만 교체:** 공개 범위·환경 변수·서비스 계정은 Terraform이 소유하므로 `--allow-unauthenticated`, `--set-env-vars`를 쓰지 않는다. 배포 후 `terraform plan`이 변경 없음을 보고해 역할 분리가 유지됨을 확인했다.
- **배포 전 typecheck·test 실행:** 테스트가 실패하면 이미지 빌드·배포 전에 중단된다.
- **트리거 경로 필터:** `docs/`, `terraform/`만 바뀐 push는 배포하지 않는다. 테스트·설정 파일(`test/`, `tsconfig*.json`, `vitest.config.ts`)은 CI 결과에 영향을 주므로 포함했다.
- **배포 후 스모크 테스트:** 배포 명령 성공만으로는 앱이 실제로 응답하는지 알 수 없어 운영 URL의 헬스 체크를 마지막 단계에 두었다. 이 단계가 Cloud Run 예약 경로 문제를 바로 드러냈다.
- **이미지 정리 정책은 후속 작업으로 분리:** 비용 검토 결과 당장은 무료 한도 안이므로, 예정된 task를 먼저 끝낸 뒤 진행하기로 사용자와 결정했다.

### 이슈 & 해결
- **1차 실행 스모크 테스트 실패(run `41285335904`):** 배포는 성공했지만 운영 URL `/healthz`가 앱이 아닌 Google 404 페이지를 반환했다(`/`와 `/api/me`는 앱이 정상 응답). Cloud Run 공식 Known issues에 "`z`로 끝나는 일부 경로는 예약되어 있으니 `z`로 끝나는 경로를 피하라"고 명시되어 있다. 로컬·compose에는 이 제한이 없어 이전 task에서 드러나지 않았다. 헬스 체크를 `/health`로 바꿔 2차 실행(run `41285788050`)에서 전 단계 성공했다. 과거 task 문서의 `/healthz` 표기는 이력이므로 그대로 두었다.
- **배포 SA 권한 확인(task 1 이월):** 서비스 단위 `run.developer`와 런타임 SA actAs만으로 `gcloud run deploy`가 두 번 모두 성공해 Terraform 변경이 필요 없었다.
- **검증 중 `/trigger`가 400으로 응답:** 점검 명령의 JSON 따옴표 이스케이프 실수로 본문이 잘못된 JSON이 되어 파서가 먼저 400을 반환한 것이었다. 올바른 JSON으로 다시 호출해 토큰 없음·위조 토큰 모두 401임을 확인했다.
- **다음 task로 이월:** 운영 E2E(휴대폰 로그인·예약·텔레그램 수신·취소, 실제 OIDC 토큰으로 `/trigger` 통과), 문서 커밋 push 시 워크플로 미실행 재확인.
