# CI/CD 파이프라인 구성 작업계획

## 목표

`main` 브랜치에 push하면 GitHub Actions가 테스트 → 이미지 빌드·푸시 → Cloud Run 배포까지 자동으로 수행하게 한다.
GCP 인증은 Workload Identity Federation으로 키 없이 처리하고, 배포는 이미지 교체만 하며 공개 범위·환경 변수는 Terraform이 소유한다.
첫 배포로 placeholder 이미지를 실제 앱으로 교체해 task 7(운영 E2E 검증)을 준비한다.

## 작업 범위

- 블루프린트 Phase 6: `.github/workflows/deploy.yml`
- GitHub `Production` Environment·Variables 설정 확인 (task 1 이후 사용자가 등록 완료)
- task 1 이월: 배포 SA의 서비스 단위 `run.developer` 권한으로 `gcloud run deploy`가 되는지 확인 (부족하면 `terraform/github.tf` 보완)
- 배포 후 스모크 테스트(`/healthz`)와 Terraform 드리프트 없음 확인
- 제외: 운영 환경 기능 E2E(로그인·예약·알림 수신)는 task 7

## 세부 작업 목록

### 1단계: 사전 확인

- [x] **확인:** 사용할 GitHub Actions 최신 메이저 버전 확인 (`actions/checkout`, `actions/setup-node`, `google-github-actions/auth`, `google-github-actions/setup-gcloud`)
  - 결과(GitHub Releases API): `actions/checkout` v7, `actions/setup-node` v7, `google-github-actions/auth` v3, `google-github-actions/setup-gcloud` v3
- [x] GitHub `Production` Environment(배포 브랜치 `main`)와 Variables(`GCP_WIF_PROVIDER`, `GCP_DEPLOYER_SA`) 등록 상태 확인 (task 1에서 사용자 등록, 스크린샷 확인됨)
- [x] 워크플로가 실행할 명령(`npm ci`, `typecheck`, `test`, `docker build`)이 깨끗한 체크아웃에서 성공하는지 로컬 확인
  - 결과: 커밋된 파일만 복사한 디렉터리에서 `npm ci`, typecheck, 테스트 112개, `docker build` 성공

### 2단계: 워크플로 작성 (`.github/workflows/deploy.yml`)

- [x] 트리거: `main` push(앱 관련 경로만), `workflow_dispatch`
  - 경로: `src/**`, `public/**`, `test/**`, `package.json`, `package-lock.json`, `tsconfig.json`, `tsconfig.build.json`, `vitest.config.ts`, `Dockerfile`, `.dockerignore`, 워크플로 파일 자체
- [x] 동시 실행 방지(`concurrency`, 진행 중인 배포는 취소하지 않음)
- [x] 권한 최소화: `contents: read`, `id-token: write`
- [x] `environment: Production` (Environment Variables 사용, 배포 브랜치 제한 적용)
- [x] 단계: 체크아웃 → Node 22(npm 캐시) → `npm ci` → `typecheck` → `test` → WIF 인증 → gcloud 설정 → Artifact Registry Docker 인증 → 이미지 빌드·푸시(태그 = 커밋 SHA) → `gcloud run deploy`(이미지만 교체) → 배포 URL `/healthz` 스모크 테스트
- [x] `--allow-unauthenticated`, `--set-env-vars` 등 Terraform 소유 설정은 지정하지 않음

### 3단계: 배포 실행 (사용자 push)

- [ ] 사용자에게 `git push` 요청 → 워크플로 실행
- [ ] GitHub API(공개 저장소)로 실행 결과·단계별 상태 확인
- [ ] 실패 시 원인 분석 후 수정 (특히 배포 SA 권한 부족 여부)

### 4단계: 배포 결과 검증

- [ ] Cloud Run 최신 리비전 이미지가 이번 커밋 SHA 태그인지 확인 (`gcloud run services describe`)
- [ ] 리비전의 서비스 계정·환경 변수·시크릿 참조가 Terraform 정의 그대로 유지되는지 확인
- [ ] 운영 URL: `/` 로그인 페이지, `/healthz` 200, `/api/me` 401, 토큰 없는 `/trigger` 401, CSP 헤더(production, `upgrade-insecure-requests` 포함)
- [ ] `terraform plan`이 "No changes" (이미지 교체가 드리프트로 잡히지 않음)
- [ ] **확인:** 배포 SA의 서비스 단위 `run.developer` + 런타임 SA actAs 권한만으로 배포 성공 여부 기록
- [ ] 문서·Terraform만 바뀐 push는 워크플로가 실행되지 않는지 확인 (task 문서 커밋 push로 확인)

## 완료 기준

- `main` push로 워크플로가 실행되어 테스트 → 이미지 푸시 → Cloud Run 배포 → 스모크 테스트까지 성공한다
- Cloud Run 서비스가 커밋 SHA 태그 이미지로 동작하고, 환경 변수·서비스 계정·공개 범위는 Terraform 정의 그대로다
- 운영 URL에서 로그인 페이지가 나오고 보호된 엔드포인트는 `401`을 반환한다
- 배포 후 `terraform plan`이 변경 없음을 보고한다
- 배포 SA 권한 충분 여부가 확인·기록되어 있다
