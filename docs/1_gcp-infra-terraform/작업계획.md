# GCP 인프라 Terraform 구성 작업계획

## 목표

블루프린트 Phase 0(수동 사전 작업)과 Phase 1(Terraform 인프라 정의)을 완료해, 이후 task들이 사용할 GCP 인프라를 코드로 프로비저닝한다.
Cloud Tasks 큐, Cloud Run 서비스(placeholder 이미지), 서비스 계정·IAM, Secret Manager, Artifact Registry, GitHub Actions용 Workload Identity Federation을 Terraform으로 정의한다.
state는 GCS에 두어 여러 컴퓨터에서 작업을 이어갈 수 있게 하고, 비밀값은 write-only 속성으로 넣어 tfstate에 남지 않게 한다.

## 작업 범위

- Phase 0: Terraform state 버킷 생성, OAuth 동의 화면 설정, OAuth Client 발급 (사용자 수동 작업)
- Phase 1: `terraform/` 디렉터리의 모든 `.tf` 파일 작성 및 `.terraform.lock.hcl` 생성
- `terraform apply`(사용자 실행) 후 리소스와 output 검증
- 제외: 애플리케이션 코드, Dockerfile, GitHub Actions 워크플로 (task 2 이후)

## 완료 기준

- `terraform fmt -check -recursive`, `terraform validate`가 통과한다
- `terraform apply`가 성공하고(postcondition 포함), 이후 `terraform plan`이 "No changes"를 출력한다
- 큐 `reminder-queue`, Cloud Run `reminder-api`, 시크릿 `telegram-bot-token`·`session-secret`, SA `reminder-api`·`reminder-tasks-invoker`·`reminder-deployer`, WIF Provider `github-actions`가 GCP에 존재한다
- Cloud Run 서비스 URL이 `https://reminder-api-371125433847.asia-northeast3.run.app`이고 placeholder 페이지가 응답한다
- 비밀값(봇 토큰, 세션 키)이 Git 추적 파일과 tfstate에 평문으로 존재하지 않는다
- `.terraform.lock.hcl`이 생성되어 커밋 대상에 포함된다
