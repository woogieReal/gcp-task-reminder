# Artifact Registry 이미지 정리 정책 작업계획

## 목표

배포할 때마다 커밋 SHA 태그 이미지가 쌓여 Artifact Registry 무료 저장 한도(0.5GB)를 넘지 않도록, 최근 5개 이미지만 남기는 정리 정책을 Terraform으로 추가한다.
현재는 배포 1회당 버전(digest)이 3개(이미지 인덱스, 실제 이미지, 빌드 출처 증명) 생겨 "최근 N개 버전" 정책이 이미지 단위로 맞지 않으므로, 빌드 출처 증명을 끄고 배포 1회 = 버전 1개가 되게 정리한다.

## 작업 범위

- `terraform/registry.tf`: 정리 정책(최근 5개 버전 KEEP, 나머지 DELETE)
- `.github/workflows/deploy.yml`: 이미지 빌드 시 provenance·SBOM 증명 비활성화
- 블루프린트 반영(registry 명세, 후속 작업 완료 처리, 운영 주의사항)
- 제외: 이미 쌓인 이미지의 수동 삭제(정책이 주기적으로 정리)

---

## 세부 작업 목록

### 1단계: 사전 확인

- [x] 현재 저장소 상태 기록: 버전 수, 용량, 배포 1회당 생성되는 버전 구성
  - 결과: 버전 9개(배포 3회 × 3), 102.4MB. 배포 1회 = 이미지 인덱스(커밋 SHA 태그) + 실제 이미지(약 87MB) + 빌드 출처 증명(1.6KB)
- [x] **확인:** google provider 8.x의 `google_artifact_registry_repository` 정리 정책 스키마(`cleanup_policies`, `most_recent_versions`, `condition`, `cleanup_policy_dry_run`)와 KEEP·DELETE 우선순위, 정책 실행 주기를 공식 문서로 확인
  - 결과: provider 스키마에 `cleanup_policies`(set: `id`, `action`, `condition{tag_state, older_than, …}`, `most_recent_versions{keep_count, package_name_prefixes}`)와 `cleanup_policy_dry_run` 존재. 공식 문서: 양쪽에 해당하면 KEEP 우선, 약 하루 안에 적용, keepCount는 패키지별, 부모 manifest가 참조하는 이미지는 삭제하지 않음, 삭제 이력은 Data Access 감사 로그(데이터 쓰기 로깅 활성화 필요)
- [x] **확인:** `docker build`의 provenance·SBOM 비활성화 옵션과, 비활성화 시 단일 이미지 manifest로 푸시되는지 확인
  - 결과: `docker buildx build --help`에 `--provenance`, `--sbom` 옵션 확인. 단일 manifest 여부는 배포 후 저장소 버전으로 확인(4단계)

### 2단계: 빌드 출처 증명 비활성화

- [x] 워크플로 이미지 빌드에 `--provenance=false --sbom=false` 추가 (배포 1회 = 태그된 이미지 1개)
- [x] 로컬에서 같은 옵션으로 빌드 성공 확인

### 3단계: 정리 정책 (Terraform)

- [x] `registry.tf`에 정책 추가: `keep-recent-5`(KEEP, 최근 5개 버전), `delete-others`(DELETE, 태그 상태 무관)
- [x] `cleanup_policy_dry_run = false` 명시
- [x] `terraform fmt -check`, `validate`, `plan` (변경은 저장소 정책 갱신 1건만인지 확인)
  - 결과: fmt·validate 통과, plan `0 to add, 1 to change, 0 to destroy` (저장소에 정책 2개 추가)
- [ ] 사용자 `terraform apply`

### 4단계: 배포 및 검증

- [ ] 사용자 커밋·push → 워크플로 성공, 새 이미지가 버전 1개(태그 = 커밋 SHA)로 푸시되는지 확인
- [ ] `gcloud artifacts repositories describe`로 정책 2개 적용·dry-run 꺼짐 확인
- [ ] 운영 서비스 정상(`/health` 200), `terraform plan` 변경 없음
- [x] 정책 실행 결과(오래된 버전 삭제)는 실행 주기 이후 확인 가능하므로, 확인 방법을 블루프린트 운영 주의사항에 기록
  - 결과: 블루프린트 8장에 "이미지 정리와 롤백" 항목 추가(롤백 한계, `gcloud artifacts docker images list`로 확인, 삭제 이력은 Data Access 감사 로그 필요)

## 완료 기준

- Terraform으로 정리 정책(최근 5개 KEEP, 나머지 DELETE)이 적용되고 `terraform plan`이 변경 없음을 보고한다
- 배포 1회당 Artifact Registry 버전이 1개만 생성된다
- 배포 워크플로와 운영 서비스가 정상 동작한다
- 정책 실행 확인 방법과 주의사항(오래된 리비전으로 롤백 불가 등)이 블루프린트에 기록된다
