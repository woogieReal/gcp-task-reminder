### 주요 결정 사항
- **외부 연동을 인터페이스(`TaskService`, `TelegramService`)로 분리해 `createApp`에 주입:** 자동 테스트는 실제 API를 호출하지 않고 mock으로 경계값을 검증하고, 로컬 수동 검증에서만 실제 큐와 텔레그램을 쓴다(블루프린트 테스트 원칙).
- **태스크 구성(`buildTask`)과 변환(`toReminder`)을 순수 함수로 분리:** Cloud Tasks 클라이언트 없이 대상 URL·OIDC·본문·예약 시각을 정확히 검증할 수 있다.
- **API는 절대 시각(`scheduleAt`)만, UTC 오프셋 필수:** 오프셋 없는 시각은 서버 시간대에 따라 해석이 달라지므로 거부한다. "10분 후" 같은 상대 시간은 task 5 프런트엔드가 변환한다.
- **`/trigger` 응답 규칙:** 발송 성공은 `200`, 텔레그램 실패는 `500`(Cloud Tasks 재시도), 본문 오류는 `200`(재시도해도 결과가 같으므로 차단).
- **텔레그램 `parse_mode` 미지정:** 사용자가 입력한 문자열이 Markdown/HTML 서식으로 해석되지 않게 했다.
- **에러에서 토큰 제거:** axios 에러 객체에는 토큰이 포함된 요청 URL이 들어 있으므로, 상태 코드와 텔레그램 설명만 새 에러로 옮겨 로그 유출을 막았다.
- **취소 시 ID 형식 검증 후 큐 경로와 조합:** 임의의 전체 리소스 경로를 받지 않아 다른 큐의 태스크를 지울 수 없다.

### 이슈 & 해결
- **Docker Desktop 미기동:** 1차 수동 검증은 호스트에서 같은 `.env`로 `tsx`를 실행해 진행했고, Docker Desktop 재기동 후 compose 컨테이너에서 같은 시나리오를 다시 검증했다. 컨테이너에 마운트한 ADC로 Cloud Tasks 인증이 동작하는 것도 확인했다.
- **vitest mock 타입 오류:** `vi.fn()`이 서비스 인터페이스 타입과 맞지 않아 typecheck가 실패했다. `vi.fn<TaskService['create']>()`처럼 시그니처를 지정하고 `Mocked`/`Mock` 타입을 사용해 해결했다.
- **테스트 태스크 정리:** 수동 검증용 태스크는 1일 뒤로 예약해 검증 중 실제 실행되지 않게 하고, 검증 후 삭제해 큐를 0건으로 유지했다.
- **다음 task로 이월:** `/api/*`·`/trigger` 인증과 `SKIP_TRIGGER_AUTH` 사용(task 4). 텔레그램 영구 4xx도 재시도되는 점은 현재 규모에서 허용.
